# 행복회로 버킷리스트 개발일지 — PM/UI 개선판

- 프로젝트: `data09-23` 행복회로 버킷리스트
- 대상: GitHub Pages 정적 웹 서비스
- 작업일: 2026-09-29
- 작업 범위: 서비스 디자인, 브랜드 요소, 공개 서비스 메타데이터, UX 개선, 회귀 테스트
- 원칙: 기존 계산/저장 기능과 DOM ID 계약을 유지하고 디자인 레이어만 확장

## 1. 작업 배경

기존 버전은 복권 당첨 시나리오, 버킷리스트, 안전금고, 월별 현금흐름, 퇴사 가능 기간, JSON 저장/복원 등 핵심 기능이 충분히 구현되어 있었다. 반면 첫 화면이 즉시 업무 입력 폼으로 시작해 외부 사용자가 서비스 목적을 빠르게 파악하기 어렵고, 브랜드 로고·히어로·사용 흐름·시각적 위계가 약해 “완성된 외부 서비스”보다는 “기능 구현 과제 화면”에 가까운 인상을 주었다.

따라서 기능 로직을 재작성하지 않고 다음 목표로 UI를 개선했다.

1. 첫 5초 안에 서비스 목적을 이해할 수 있게 한다.
2. “복권 계산기”보다 “꿈 예산 시뮬레이터”라는 정체성을 강화한다.
3. 외부 공개 시 사용할 수 있는 로고, 컬러, 메타데이터를 추가한다.
4. 입력 영역은 기존 기능을 유지하면서 카드형 UI와 단계 표시를 적용한다.
5. 모바일/데스크톱 반응형 및 접근성 기능을 유지한다.

## 2. 수정 파일

| 파일 | 수정 내용 |
|---|---|
| `index.html` | 브랜드 헤더, SVG 로고, 히어로, 3단계 사용 흐름, 단계 라벨, 결과 안내문, 공개용 SEO/OG 메타데이터, 푸터 개선 |
| `css/style.css` | 전체 디자인 시스템 재정의, 브랜드 팔레트, 히어로, 서비스 카드, 버튼, 폼, 결과 대시보드, 반응형, 인쇄 스타일 개선 |
| `js/ui.js` | 계산 로직과 분리된 화면 전용 인터랙션 추가: 앵커 부드러운 이동, 스크롤 시 헤더 깊이감 처리 |
| `assets/logo.svg` | 행복회로의 꿈/순환/성장을 상징하는 자체 SVG 로고 마크 추가 |

기존 핵심 로직 파일 `js/app.js`, `js/logic.js`, `js/store.js`, `js/examples.js`의 계산 계약은 변경하지 않았다.

## 3. 디자인 시스템 개선

### 3.1 컬러

기존 단일 보라색 중심에서 다음 의미 체계로 확장했다.

- Primary `#5B3DF5`: 꿈, 상상, 브랜드 행동 버튼
- Accent `#21A990`: 성장, 현금흐름, 긍정적 진행
- Background `#F6F7FB`: 장시간 입력 시 눈의 피로를 낮추는 중성 배경
- Surface `#FFFFFF`: 카드/입력 표면
- Warning/Negative/Reserve: 기존 의미색은 기능적 일관성을 위해 유지

### 3.2 로고

`assets/logo.svg`를 신규 작성했다. 별은 “꿈”, 순환 궤도는 “행복회로”, 끝의 점은 “계획을 실행 가능한 숫자로 전환하는 지점”을 표현한다. 외부 이미지/CDN 없이 저장소 자체에서 제공된다.

### 3.3 히어로

첫 화면에 다음 메시지를 추가했다.

> 당첨되는 상상에서 끝내지 말고, 내 꿈의 가격을 계산해 보세요.

기능을 나열하기보다 서비스가 해결하는 사용자 문제를 먼저 보여 주도록 구성했다. CTA는 기존 `#secWins`로 이동하므로 새 기능 의존성이 없다.

### 3.4 사용 흐름

복잡한 입력 전에 다음 3단계 구조를 제시했다.

1. 당첨 시나리오
2. 꿈과 생활비
3. 미래 확인

기존 1~4 입력 섹션에는 `STEP 01`~`STEP 04` 시각 라벨을 추가해 긴 폼에서 현재 위치를 쉽게 파악하게 했다.

### 3.5 결과 영역

가장 중요한 결과 패널은 별도 그림자, 보라색 경계, `DASHBOARD` 라벨을 적용했다. 입력 영역과 결과 영역의 우선순위를 시각적으로 구분하면서 기존 결과 렌더링 DOM은 그대로 유지했다.

## 4. UX/접근성 개선

- 기존 `skip link`, `aria-live`, `label`, `focus-visible` 구조 유지
- 앵커 이동을 `js/ui.js`로 분리해 계산 코드와 결합하지 않음
- `prefers-reduced-motion` 사용자는 애니메이션/부드러운 이동을 최소화
- 360px 모바일부터 1024px 이상 2열 작업 화면까지 대응
- 필터는 작은 화면에서 1열로 전환
- 상단 헤더는 sticky 처리해 시나리오 전환과 저장 상태를 계속 확인 가능
- 인쇄/PDF에서는 히어로와 작업용 UI를 감춰 보고서 출력에 집중

## 5. 외부 공개 서비스 개선

기존 `robots=noindex`를 `index,follow`로 변경하고 다음을 추가했다.

- canonical URL
- Open Graph 제목/설명/URL
- Twitter card 기본 메타데이터
- SVG favicon
- 서비스형 title

GitHub Pages 주소를 그대로 공개할 때 검색엔진과 링크 공유가 가능한 구조다.

## 6. 코드 유지보수 원칙

디자인 관련 변경부에는 PM/UI 개선 목적을 주석으로 명시했다. 신규 화면 동작은 `js/ui.js`에만 배치하여 계산 로직과 UI 로직을 분리했다. 향후 디자이너가 CSS와 UI 인터랙션을 수정하더라도 세금/연금/현금흐름 계산 코드를 직접 건드릴 필요가 없다.
