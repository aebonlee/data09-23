## 2. 변경 안정성

이번 작업은 핵심 계산 파일의 로직을 수정하지 않고 `index.html`, `css/style.css`, `js/ui.js`, `assets/logo.svg` 중심으로 진행했다. 기존 앱에서 사용하는 DOM ID를 유지했기 때문에 `app.js`의 이벤트 바인딩과 렌더링 계약을 보존했다.

45개 자동 테스트가 모두 통과하여 다음 영역의 회귀가 없음을 확인했다.

- 세금 구간 계산
- 일시금 계산
- 연금복권 월별 흐름
- 중복 당첨/수량 계산
- 퇴사 가능 기간
- 버킷 보류/복원
- 입력 검증
- JSON 저장/복원

## 3. 배포 전 체크리스트

GitHub에 업로드하기 전에 다음 파일이 함께 올라가는지 확인한다.

```text
index.html
css/style.css
js/ui.js
assets/logo.svg
js/app.js
js/logic.js
js/store.js
js/examples.js
```

GitHub Pages 배포 후 브라우저에서 다음을 확인한다.

1. 상단 로고가 정상 표시되는지
2. “내 행복회로 시작하기” 클릭 시 당첨 내역으로 이동하는지
3. 기존 예시 프리셋이 정상 동작하는지
4. 당첨/버킷 입력 후 남은 예산이 즉시 바뀌는지
5. 새로고침 후 localStorage 데이터가 유지되는지
6. JSON 내보내기/가져오기가 정상인지
7. 모바일에서 시나리오 선택과 버튼이 가로 넘침 없이 보이는지
8. 인쇄/PDF에서 히어로와 입력용 UI가 숨겨지는지

## 5. 최종 판정

현재 소스는 기존 1단계 기능을 유지한 채 외부 공개용 브랜드/서비스 UI가 적용되었으며, GitHub Pages에 다시 배포 가능한 상태다. 기능 로직 회귀 테스트와 JavaScript/HTML 구조 점검은 통과했다.

정식 서비스 수준으로 넘어가기 전 남은 핵심 과제는 OG 대표 이미지, E2E 브라우저 테스트, 2단계 서버 기능 도입 시 개인정보/약관/데이터 출처 관리다.
