## 결정과 이유

- **숫자는 기획서에 적힌 값만.** 연금 1등 월 700만원 × 0.78 = 546만원, 2등·보너스 월 100만원 × 0.78 = 78만원, 로또 4·5등, 스피또 1등 등은 제출 기획서 2장 표 그대로이고 화면에 「기획서 기준 값 · 확인일 2026-09-29」로 표시합니다. 모두 고쳐 쓸 수 있습니다. 기획서에 없는 값(로또 1~3등, 스피또1000·2000 하위 등수)은 직접 입력으로 두고 임의 금액을 채우지 않았습니다.
- **로또 평균 자동 수집은 하지 않습니다(2단계).** 기획서도 서버 작업 또는 관리자 검수 등록으로 정해 두었고, 정적 페이지에서 외부 사이트를 긁어오지 않습니다. 평균 식 `round(ΣP/N)`(N ≤ 52, 누락 제외)만 로직에 준비했습니다.
- **세금은 정수 연산.** `G × 0.22` 를 `Math.round(G × 22 / 100)` 로, 초과분도 `× 33 / 100` 으로 계산해 부동소수 오차 없이 원 단위 반올림합니다. 과세 단위(게임·낱장)마다 세후를 먼저 구하고 수량을 곱합니다 — 로또 3등 150만원 2게임은 305만원(합쳐서 과세하면 틀림), 스피또2000 낱장 2매는 14억600만원.
- **연금 총액은 잔고에 더하지 않습니다.** 받는 달에만 수입으로 들어오고, 20년 합계는 접힌 「참고」 칸에만 둡니다(제출 기획서가 출시 차단 오류로 꼽은 항목). 2등 지급이 끝나도 1등은 계속됩니다.
- **모드 자동 판정.** 월 지급이 하나라도 있거나 일시금 수령 월이 다르면 월별 현금흐름, 아니면 일시금 예산. 일시금만 있어도 「월별로 보기」를 켤 수 있습니다. 기획서의 「모드 전환 시 별도 시나리오 생성」은 줄여서, 일시금 화면은 반복 버킷을 합계에서 빼고 알려 줍니다(기획서 10장 질문 5).
- **계산은 늘 600개월, 조회는 필요한 만큼.** 표·그래프는 시작 월부터 (마지막 지급 월, 가장 늦은 예정 지출 월) + 12개월. 퇴사 기간·첫 부족 월은 600개월 전체에서 찾습니다.
- **안전금고는 지출이 아닙니다.** 가용 = 잔고 − 안전금고로만 계산하고, 금고를 바꿔도 총잔액은 그대로입니다(AC05). 설정 한도는 「초기 사용 가능 현금」— 일시금은 당첨 후 잔고, 월별은 현재 잔고 + 시작 월 수령액으로 해석했습니다(질문 4).
- **금액 입력은 한글 단위를 받습니다.** 「1억 8천만」「5천만원」「150만」「1.5억」→ 원 정수, 바로 아래에 `= 180,000,000원 (1억 8,000만원)` 로 읽은 값을 보여 줍니다(기획서의 만원·억원 입력 보조). 잔고·안전금고·생활비는 입력하는 대로 다시 계산합니다 — 처음에 `change`(칸을 떠날 때)로 했더니, 칸을 떠나며 목록을 다시 그려 **목록 단추의 첫 클릭이 사라지는 것**을 헤드리스 검사에서 발견해 `input` 으로 바꿨습니다.
- **공유는 이미지·인쇄.** 캔버스로 요약을 그려 PNG 로 내려받습니다. 「가상 시뮬레이션」 문구는 늘 넣고, 현재 잔고·메모는 기본 숨김입니다. 링크 공유는 계정·서버가 필요해 2단계입니다.
- **DB 는 준비만.** 기획서 8장대로 1단계는 계정 없이 localStorage 입니다. 동기화(P1)를 대비해 스키마와 검증 하네스를 두었고, 당첨 행 100개·버킷/현금흐름 500개 한도와 awardUnitKey 중복 방지를 DB 제약으로도 걸었습니다.
